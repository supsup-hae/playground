# 확인하지 못한 것

단계마다 시험(가짜 카메라·가짜 채널)과 빌드로는 확인했지만, 실제 기기나 실제 자료가 있어야 하는 항목은 확인하지 못했다. 확인하면 해당 줄에 결과와 날짜를 적고 체크한다.

준비: 카메라 메뉴 `PC 연결 모드 → USB RAW 변환/백업 복원`, macOS 에서는 사진 앱·이미지 캡처를 닫는다.

## 1단계 카메라 연결 (macOS)

- [ ] 연결하면 모델 이름 "X-T5" 가 보인다
- [ ] 7슬롯 읽기 결과가 카메라 메뉴의 C1–C7 이름과 같고, 필름 시뮬레이션(D192) 값이 `analysis.md` 표와 같다 — X-T5 의 속성 코드·인코딩이 FilmKit(X100VI 기준)과 같은지가 여기서 정해진다
- [ ] 읽기 전후 카메라의 지금 선택 슬롯이 같다
- [ ] 슬롯 하나의 값 하나(예: C7 하이라이트)를 바꿔 쓰면 카메라 메뉴에 반영되고, 백업에서 복원하면 원래 값으로 돌아온다
- [ ] 로그의 슬롯 1개 쓰기 시간 × 7 이 10초 이내인가 (PRD 성공 지표)
- [ ] 슬롯 선택(D18C)이 카메라의 지금 촬영 설정까지 바꾸는가 (PRD 열린 질문)
- [ ] 카메라 이름 칸의 최대 길이
- [ ] 연결할 때마다 transaction ID 를 1 부터 세도 `ImageCaptureCore` 가 받아들이는가 (3단계에서 바꿈)

## 2단계 보관함·묶음·비교

- [x] Supabase 로그인 → 저장 → 동기화 → 원격 행 생성 (2026-10-17 사용자 확인)
- [ ] 묶음 하나로 7슬롯 쓰기가 실기기에서 10초 안에 끝나는가, 쓰기 전 자동 백업이 남는가
- [ ] 다이내믹 레인지(ISO 의존)·클래리티(드라이브 모드 의존)를 카메라가 거부할 때 로그에 경고가 남고 나머지 값은 쓰이는가 (PRD 열린 질문)
- [ ] 비교 화면의 값 이름이 카메라 메뉴 표기와 같은가

## 3단계 Android

- [ ] 갤럭시 S26 울트라에 앱 설치, 디자인 화면 맨 위의 화면 크기 기록 (에뮬레이터 411 × 914 dp 와 비교)
- [ ] 휴대폰과 X-T5 를 USB-C 로 연결하면 권한 대화상자가 뜨고, 허용하면 연결된다
- [ ] 휴대폰 전원(OTG)으로 카메라가 연결 모드에 들어가는가
- [ ] 삼성 기본 앱(사진 가져오기)이 카메라를 먼저 잡아 "다른 앱이 카메라를 쓰고 있다" 가 뜨는가
- [ ] 카메라를 꽂으면 앱을 열지 묻는가 (`USB_DEVICE_ATTACHED` 필터)
- [ ] 앱 실행부터 묶음 교체까지 30초 이내인가 (PRD 성공 지표)
- [ ] 쓰기 중 케이블을 뽑으면 연결이 정리되고 다음 작업이 "카메라가 연결되지 않았다" 로 끝나는가
- [ ] Android 에서 로그인·동기화

## 4단계 가져오기

- [ ] **EXIF 표 확인**: X-T5 원본 JPEG 와 그 사진의 레시피 값을 `samples/` 에 두면 확인한다 (`docs/plans/phase-4-import.plan.md` Task C3)
  - [ ] WB 시프트 한 칸의 원시 값(20 으로 추정)
  - [ ] 모노 WC·MG 태그(0x1049·0x104B)와 배율
  - [ ] 스무스 스킨 태그 (찾지 못함)
  - [ ] 다이내믹 레인지 태그(0x1403)
  - [ ] 필름 시뮬레이션·그레인·컬러 크롬 값이 ExifTool 표와 같은가
- [ ] 앱에서 실제 SNS 캡처·레시피 사이트 스크린샷으로 글자 가져오기 (macOS Vision)
- [ ] Android ML Kit 글자 인식, 세로로 찍은 사진의 방향 반영
- [ ] 카메라 슬롯 가져오기를 실기기에서

## 5단계 RAW 미리보기

준비: X-T5 로 찍은 RAF 한 장(카메라 메모리 카드는 넣은 채로 두어도 된다).

- [ ] RAF 보내기(0x900C·0x900D)가 성공하고, 보낸 뒤 현상 설정(0xD185)이 비어 있지 않은가
- [ ] 레시피 하나로 현상한 결과가 JPEG 로 오는가, 걸린 시간(로그 "현상: …ms")
- [ ] D185 칸 번호가 X-T5 에서도 FilmKit(X100VI) 표와 같은가: 하이라이트 −2 와 +4 처럼 크게 다른 두 레시피의 결과가 눈으로 다른가, 필름 시뮬레이션이 바뀌는가
- [ ] 모노 WC·MG 와 노출 보정 칸 (지금은 고치지 않는다)
- [ ] macOS `ImageCaptureCore` 가 약 50 MB 데이터 명령을 한 번에 받는가 (60초 제한)
- [ ] Android 에서 RAF 보내기 시간과 메모리, 1 MiB 씩 나눠 보내기
- [ ] 결과 객체를 지운 뒤 카메라 메모리 카드에 남는 파일이 없는가
- [ ] 결과 핸들로 메모리 카드의 다른 사진이 잡히지 않는가 (지금은 현상 시작 전 목록에 없던 객체 중 ObjectFormat 이 JPEG 인 것만 받는다)
- [ ] 현상 결과 객체에 GetObjectInfo(0x1008)가 되고 ObjectFormat 이 JPEG(0x3801)인가 — 아니면 결과를 찾지 못하고 30초 뒤 실패한다

## 사진 기록 1단계 촬영 정보 읽기

준비: XApp 설정에서 위치 정보 동기화를 켜고, 휴대폰과 연결된 상태로 찍은 JPEG 한 장.

- [x] XApp 으로 받은 JPEG 에 후지 MakerNote 가 남고 필름 시뮬레이션이 읽힌다 (2026-10-19, 표본 2장, Eterna)
- [ ] 위치 동기화를 켜고 찍은 사진의 GPS IFD 에 값이 들어오고, XApp 으로 받을 때 지워지지 않는가 (표본 2장은 GPS 값이 모두 0)
- [ ] 남위·서경 좌표 (가짜 EXIF 로만 확인)
- [ ] MakerNote `0x1438` 이 촬영 번호인가 (표본 두 장이 1422, 1423 으로 이어진다)
- [ ] 표본의 레시피 값이 카메라에 넣은 값과 같은가: Eterna, DR400, 그레인 강·대, 하이라이트 −2, 섀도 +1, 컬러 +3, 샤프니스 0, 클래리티 +1, NR −4, CC 강, FX 블루 강, WB 오토 R+4 B−7
